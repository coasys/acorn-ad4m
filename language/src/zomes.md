# Acorn zome call shapes (verified against `happs/happ/zomes/**`)

Hash fields cross the bridge as `ActionHashB64` / `AgentPubKeyB64` base64
strings (`uhCkk…` / `uhCAk…`) — WireRecord's `actionHash`/`entryHash` are
`*B64` too, so everything is a plain string in this module. `ZomeFnInput<T>`
is `{ input: T, local?: bool }` (`hdk_crud/src/helper.rs`); `local: true` is
the correct choice on this full-arc rig.

| Class | fetch (read for update) | create | update | delete |
|---|---|---|---|---|
| AcornOutcome | `fetch_outcomes { input: { Specific: [entryHash] } \| { All: null }, local: true }` → `WireRecord[]` | `create_outcome_with_connection({ entry, maybeLinkedOutcome })` → `{ outcome: WireRecord, maybeConnection: WireRecord? }` | `update_outcome({ entry, actionHash })` | `delete_outcome_fully({ input: actionHash, local: true })` → `{ outcomeActionHash, deletedConnections, deletedOutcomeMembers, deletedOutcomeVotes, deletedOutcomeComments, deletedEntryPoints }` |
| AcornConnection | `fetch_connections` (same input) | `create_connection(entry)` → WireRecord | `update_connection({ entry, actionHash })` | `delete_connection(actionHash)` |
| AcornEntryPoint | `fetch_entry_points` | `create_entry_point(entry)` | `update_entry_point({ entry, actionHash })` (exists; unused by the Acorn UI) | `delete_entry_point(actionHash)` |
| AcornOutcomeComment | `fetch_outcome_comments` | `create_outcome_comment(entry)` | `update_outcome_comment({ entry, actionHash })` | `delete_outcome_comment(actionHash)` |
| AcornOutcomeMember | `fetch_outcome_members` | `create_outcome_member(entry)` | `update_outcome_member({ entry, actionHash })` (exists; unused by the Acorn UI) | `delete_outcome_member(actionHash)` |
| AcornTag | `fetch_tags` | `create_tag(entry)` | `update_tag({ entry, actionHash })` | `delete_tag(actionHash)` |
| AcornProjectMeta | `fetch_project_metas` (crud! plural) or `fetch_project_meta { input: null, local: true }` (custom, singular) → WireRecord | `simple_create_project_meta({ input: entry, local: true })` → WireRecord (refuses a second meta: `OnlyOneOfEntryType`) | `update_project_meta({ entry, actionHash })` | `delete_project_meta(actionHash)` (exists; not exposed — shape has no destructor) |
| AcornMember | `fetch_members { input: null, local: true }` → `WireRecord[]` | — (created by `join_project` in B5) | — | — |
| AcornProfile | `fetch_agents { input: null, local: true }` → bare `Profile[]` (no WireRecord) | `create_whoami(entry)` (zome `profiles`) → WireRecord | `update_whoami({ entry, actionHash })` (zome `profiles`; B5) | — |

Notes:

- `maybeLinkedOutcome` is `{ outcomeActionHash, relation, siblingOrder }`;
  `relation: "ExistingOutcomeAsParent"` makes the named (existing) outcome
  the new one's parent (`projects/outcome/crud.rs:126-137`). The sibling
  `ExistingOutcomeAsChild` makes it the child.
- `create_outcome` (without connection) also exists; the write side always
  uses `create_outcome_with_connection` with `maybeLinkedOutcome: null` for
  the unlinked case, matching the UI.
- `update_*` takes `{ entry: <complete new entry>, actionHash }` where
  `actionHash` is the record's create (original) action hash — the mount
  address. Reads for read-modify-write may use `{ Specific: [entryHash] }`
  or `{ All: null }`; this module uses `All` + an actionHash match so the
  same call serves every class.
- `update_entry_point` / `update_outcome_member` are generated by the
  `crud!` macro and work, though the Acorn UI never calls them (it deletes
  and recreates). They are exposed because the shapes mark the props
  writable; AcornProfile stays out of B3 (`update_whoami` is B5's).
